When merged, this pull request will add TTL-based eviction to the report cache — entries expire after a set time. The TTL replaces the old behavior: entries no longer live until the nightly restart clears them. `cache.ttl_hours` in `config/settings.yaml` sets the TTL and defaults to 6 hours. The export endpoint reads the same cache, so exports get the same 6-hour bound.
Support promised customers that report data is never more than 8 hours old, but nothing enforced that promise until now. This change enforces that promise.
**Perf numbers are staging-only.** p95 for `/reports` dropped from 840ms to 210ms after warm-up. Prod is unmeasured and carries about 10x staging's traffic, so treat the prod number as an estimate.
**Deploy order matters.**
1. Run migration `2024_add_cache_meta.sql`.
2. Set `cache.ttl_hours` in the prod overrides.
3. Deploy `worker` before `web`.
**Worst-case staleness is 6 hours 15 minutes.** The eviction sweep runs every 15 minutes, so a fresh entry can sit for one extra cycle before eviction. The extra 15 minutes still fits inside the 8-hour promise that support made to customers.
