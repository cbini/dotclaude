When merged, this pull request will add TTL (time to live) eviction to the report cache. Cache entries now expire 6 hours after write, not at the next nightly restart. The TTL comes from `cache.ttl_hours` in `config/settings.yaml` (default: 6). The export endpoint reads the same cache, so exports get the same 6-hour bound.
Support promised customers report data no staler than 8 hours. This change enforces that promise.
Deploy in this order:
1. Run migration `2024_add_cache_meta.sql`
2. Set `cache.ttl_hours` in the prod overrides
3. Deploy the worker
4. Deploy web
Performance: p95 latency (95th percentile) for `/reports` dropped from 840ms to 210ms in staging, after cache warm-up. Prod is unmeasured. It carries about 10x staging traffic, so treat the staging number as a guess for prod, not a guarantee.
Known gap: the eviction sweep runs every 15 minutes, so worst-case staleness is 6 hours 15 minutes, not a flat 6 hours. That worst case still fits within the 8-hour SLA.
