When merged, this pull request will add time-to-live (TTL) eviction to the report cache. Entries now expire 6 hours after write. Before this change, they lived until the nightly restart cleared them. `cache.ttl_hours` in `config/settings.yaml` controls the TTL length and defaults to 6 hours. The export endpoint reads the same cache, so exports also get the 6-hour bound.
Support promised customers report data no staler than 8 hours — a service-level agreement (SLA). This TTL enforces it.
Deploy in this exact order:
1. Run migration `2024_add_cache_meta.sql`.
2. Set `cache.ttl_hours` in the prod overrides.
3. Deploy the worker.
4. Deploy web.
- The eviction sweep runs every 15 minutes, so worst-case staleness is 6h15m, not the full 6-hour TTL. That is still inside the 8-hour SLA, but is a real gap worth knowing about.
- The 95th-percentile (p95) response time for `/reports` fell from 840ms to 210ms after warm-up — measured in staging, not prod. Prod carries about 10x the traffic, so this prod figure is inferred, not measured.
