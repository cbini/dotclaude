When merged, this pull request will add time-to-live (TTL) eviction to the report cache. Entries now expire 6 hours after write. Before this change, they lived until the nightly restart cleared them.
New config: `cache.ttl_hours` in `config/settings.yaml`, default 6.
The export endpoint reads the same cache, so exports get the same 6-hour TTL.
Support's promise to customers: report data is no more than 8 hours stale. Nothing enforced that limit until this change.
In staging, p95 latency for `/reports` — the 95th-percentile response time — dropped from 840ms to 210ms after warm-up. I did not measure prod. Prod runs about 10x the traffic, so this drop may not carry over — confirm prod's own p95 separately.
Deploy in this order:
1. Run migration `2024_add_cache_meta.sql`.
2. Set `cache.ttl_hours` in the prod overrides.
3. Deploy the worker before the web service.
Known gap: the eviction sweep runs every 15 minutes, so worst-case staleness is 6h15m, not the 6-hour TTL. It still fits inside the 8-hour limit.
