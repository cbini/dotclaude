When merged, this pull request will add time-to-live (TTL) eviction to the report cache. Entries now expire 6 hours after write, not at the next nightly restart. The eviction period comes from `cache.ttl_hours` in `config/settings.yaml` (default: 6). The export endpoint reads the same cache, so exports get the same 6-hour bound.
The support team promised customers that report data is never more than 8 hours stale. This change is what enforces that promise.
- Staging p95 for `/reports` dropped from 840ms to 210ms after cache warm-up, but I did not measure prod. Prod carries roughly 10 times the staging traffic. Treat the prod p95 as a guess until we check it there.
- Eviction sweeps run every 15 minutes, so worst-case staleness is 6h15m, not 6h. That gap still fits inside the 8-hour promise to customers.
Deploy in this order:
1. Run the `2024_add_cache_meta.sql` migration.
2. Set `cache.ttl_hours` in the prod overrides.
3. Deploy the worker before the web service.
