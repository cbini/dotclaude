When merged, this pull request will evict report cache entries 6 hours after write.
Right now, entries live until the nightly restart clears them. Support promised customers report data no staler than 8 hours (the 8-hour promise), but nothing enforces it today. This change enforces it directly: a sweep evicts each entry once its 6-hour time-to-live (TTL) passes.
The export endpoint reads the same cache, so exports now carry the same 6-hour bound.
The TTL comes from `cache.ttl_hours` in `config/settings.yaml`. Default: 6 hours.
**Deploy order matters:**
1. Run the migration `2024_add_cache_meta.sql`.
2. Set `cache.ttl_hours` in the prod overrides.
3. Deploy the worker before the web service.
**Staging numbers only.** 95th-percentile latency (p95) for `/reports` fell from 840ms to 210ms in staging after warm-up — verified. Prod runs about 10x the traffic. The prod number is inferred, not measured.
**Worst case: 6 hours 15 minutes, not 6 hours.** The sweep runs every 15 minutes, so an entry can sit up to 15 minutes past its TTL — still inside the 8-hour promise.
