When merged, this pull request will add time-to-live (TTL) eviction to the report cache. Entries now expire 6 hours after write instead of living until the nightly restart clears them.
The export endpoint reads the same cache, so exports pick up the same 6-hour bound. Config: `cache.ttl_hours` in `config/settings.yaml`, default 6.
Support promised customers that report data is never more than 8 hours old. This change is what enforces that promise.
**Deploy order matters — check before merging:**
1. Run the migration `2024_add_cache_meta.sql`.
2. Set `cache.ttl_hours` in the prod overrides.
3. Deploy worker before web.
**The prod number is not verified.** Staging p95 (95th-percentile) latency for `/reports` dropped from 840ms to 210ms after cache warm-up. We did not measure prod, and prod traffic runs about 10x staging's. Treat the prod number as a guess, not a verified result.
**Worst-case staleness is 6 hours 15 minutes, not 6 hours.** The eviction sweep runs every 15 minutes, so a stale value can sit for one more sweep cycle after its TTL passes. That extra 15 minutes still lands inside the 8-hour promise to customers, so it holds.
