When merged, this pull request will add time-to-live (TTL) eviction to the report cache. Entries now expire 6 hours after write, instead of living until the nightly restart clears them. The export endpoint reads the same cache, so exports pick up the same 6-hour bound. Support promised customers that report data stays no more than 8 hours stale. This change enforces that promise.
- `cache.ttl_hours` in `config/settings.yaml` defaults to 6.
- In staging, p95 latency (95th-percentile response time) for `/reports` fell from 840ms to 210ms once the cache warmed up.
- The prod p95 number is inferred, not measured. Prod carries about 10 times staging's traffic, so treat that estimate as a guess.
- The eviction sweep runs every 15 minutes, so worst-case staleness is 6 hours 15 minutes, not exactly 6 hours. That worst case is still less than the 8-hour promise.
- This change does not include a rollback plan for the migration or the ordered deploy. Add one before merging.
Deploy in this order:
1. Run migration `2024_add_cache_meta.sql`.
2. Set `cache.ttl_hours` in the prod config overrides.
3. Deploy the worker before the web service.
